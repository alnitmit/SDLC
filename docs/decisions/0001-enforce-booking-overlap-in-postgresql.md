# ADR-0001 Согласованность бронирования в PostgreSQL

## Контекст и постановка задачи

Несколько экземпляров API могут одновременно подтвердить бронь на пересекающиеся интервалы одного автомобиля.

Связанные требования — REQ-FUNC-002, REQ-REL-001 и предлагаемый CHG-001. Подробности см. в [SDD](../../sdd/sdd.md) и [SRS](../../srs/srs-template.md).

## Рассмотренные варианты

- Блокировка Redis с проверкой в приложении.
- Сериализация транзакций без ограничения диапазонов.
- Ограничение диапазонов в PostgreSQL с блокировками по сценарию SRS.

## Итог решения

Основная гарантия — EXCLUDE USING gist по автомобилю и активному диапазону занятости. Для переходов состояния используется SELECT … FOR UPDATE. Предусмотренная в SRS блокировка Redisson сокращает конкуренцию на пути формирования брони. В варианте с CHG-001 оба типа занятости проверяются тем же ограничением.

### Последствия

Понадобятся миграция Flyway и расширение btree_gist. API переводит отказ ограничения в ответ 409. Таймаут или потеря блокировки Redis не снимает ограничение PostgreSQL.

### Подтверждение

Проверить 1000 конкурентных запросов с двух экземпляров приложения, запросы на смежные интервалы и, при принятии CHG-001, гонку между бронью и блокировкой на обслуживание.
